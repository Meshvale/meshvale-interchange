# OBJ files and verified bundles

Contract version **0.2.1**, development interface. [obj_files.h](../include/meshvale/interchange/obj_files.h) owns type shapes. [The text adapter](obj.md) owns mesh/material semantics and its numerical bound. This contract owns filesystem resources and publication; it does not establish a release or CLI.

## OBJ-FILE-001: Owned resource snapshots

`read_obj_file` reads an OBJ and every referenced MTL and supported texture file into an owned `ObjFileAsset`. Its default resource root is the input directory; callers can explicitly choose an enclosing directory for references such as `../textures/image.png`. References must remain within that root both lexically and after resolving filesystem links. Only regular files are accepted. Inside-root links are read as bytes; snapshots and published bundles contain ordinary files, not links. Reading does not modify inputs. Cancellation returns no asset; allocation failures propagate.

The snapshot contains a relative OBJ path, ordered distinct material-library paths, and path-sorted resource records. No absolute source location is required for publication. Each MTL retains its own location and bytes; combined MTL text, joined with a newline where necessary, supplies the text adapter. Textures resolve relative to the MTL containing their directive. This is the adapter's explicit resolution policy. Images remain opaque bytes; file presence does not prove image decodability, shader equivalence or material validity.

OBJ `mtllib` uses whitespace-separated filenames, including multiple filenames on one line. Quoted/escaped library filenames and library paths containing whitespace are unsupported. MTL texture filenames may contain spaces, with options preceding the filename as parsed by the pinned tinyobjloader helper. Quoted filenames, continuations and unknown MTL directives fail explicitly. Supported scalar directives are `newmtl`, `Ka`, `Kd`, `Ks`, `Ke`, `Tf`, `Ns`, `Ni`, `d`, `Tr`, `illum`, `sharpness`, `Pr`, `Pm`, `Ps`, `Pc`, `Pcr`, `aniso`, `anisor`; supported resource directives are `map_Ka`, `map_Kd`, `map_Ks`, `map_Ns`, `map_d`, `map_bump`, `map_Bump`, `bump`, `map_disp`, `map_Disp`, `disp`, `refl`, `map_Pr`, `map_Pm`, `map_Ps`, `map_Ke`, `norm`. Every occurrence is inspected, including overridden definitions.

Resource names use relative portable paths. Backslashes in references are treated as separators; absolute, drive/network, escaping, control-character and Windows-reserved names fail. File/directory prefix conflicts and ASCII case aliases fail rather than producing platform-dependent collisions. Unicode names are supported through filesystem paths, but cross-filesystem Unicode normalization/case equivalence is not promised. Malformed mesh storage may remain a raw asset with diagnostics; publication still requires a successful checked text export.

## OBJ-BUNDLE-001: Verify before publication

`publish_obj_bundle` consumes a const snapshot and a new destination directory whose parent already exists. An existing destination, including an empty directory, file or dangling link, fails. Publication does not reread original sources. Callers may replace the document's mesh with an accepted processing candidate; material-library bytes and resource records must remain coherent.

The implementation creates an exclusive temporary sibling directory, writes canonical OBJ text with the original relative library references, and copies snapshot resource bytes. Optional supplemental files can carry a caller's report or other output; they must not collide with mesh/resources. The staged OBJ is reloaded using the staging root. Verification checks canonical supported mesh semantics, library ordering, every resource path/byte, supplemental bytes and the complete staged file inventory. Success is reported only after final directory publication.

Optional `on_verified(reloaded_asset, files)` runs synchronously after initial staged reload, resource/byte and inventory verification. It receives a const owned reloaded snapshot and a path-sorted vector of the exact verified OBJ/resource/static-supplement bytes, using relative portable paths. It returns additional `ObjResource` supplemental files. Callers can compute artifact hashes and prepare receipts from these verified bytes without recreating serialization or accessing the staging directory. Dynamic files are validated for portable paths and collisions, written, read back byte-for-byte, and included in the final inventory; all original verified bytes are checked again after the callback. The returned supplements are excluded from its input inventory, avoiding self-referential report hashes. They become visible only if the entire bundle commits.

The callback runs at the verification phase before the publication progress callback; it does not run after a failed initial check or after commit. Exceptions produce `obj.verified_callback_failed`; cancellation retains its normal outcome and cleanup. Native allocation failures propagate. Neither callback may mutate the source or staging filesystem. No callback receives an absolute source/staging location. This is a neutral supplemental-file facility, not an application report schema or predicate implementation.

Finalization uses no-replace platform operations: [Windows `MoveFileExW` without replacement/copy flags](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw), [Linux `renameat2` with `RENAME_NOREPLACE`](https://man7.org/linux/man-pages/man2/rename.2.html), or [macOS exclusive rename](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming). Unsupported platforms/filesystems fail without an overwrite fallback. A competing destination created before finalization is preserved. Desktop tests exercise local filesystems; network filesystem ambiguity, power-loss durability, crash cleanup and hostile concurrent modification of staging are outside the guarantee.

Cancellation is cooperative before each phase and file operation. `on_phase` is a synchronous progress callback before phase work; exceptions fail the operation. Cancellation observed before finalization publishes no bundle. Once the native publication operation succeeds, the outcome is `published`; a later cancellation cannot undo it. Failure/cancellation attempts staging cleanup and reports `obj.cleanup_failed` if cleanup fails. Callbacks must not mutate the input snapshot. No callback runs after publication.

`ObjBundleResult` separates outcome from the last phase reached. A successful entry is relative to the final bundle. Diagnostic subjects use relative resources or operation labels rather than absolute input locations. C++ allocation failures propagate with best-effort staging cleanup; callers must translate them into their own execution/reporting outcomes.

## Acceptance

Focused original fixtures cover multiple library directories, texture options/space-containing names, shared resources, an explicit enclosing root, missing/outside-root resources, unknown directives, source protection, malformed raw geometry and path collisions. Bundle tests cover verified reload, supplemental files, existing/racing destinations, cancellation at every phase, copy/reload failures and callback exceptions. Installed consumers must use the public header and installed target. These checks do not establish the broader format or application release matrix.

## C++ header compatibility

`<meshvale/interchange/obj_files.h>` is the canonical self-contained C++20 header. The installed `<meshvale/interchange/obj_files.hpp>` path remains a forwarding header to the same definitions for source compatibility. Including canonical and legacy paths together is supported. Public type/function names, data layout and behavior are unchanged; this migration does not promise a stable binary ABI or schedule legacy-header removal. New consumers should use `.h` paths.
